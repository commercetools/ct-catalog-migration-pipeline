The first request of a customer or order stage in `load --execute` holds the record that shows the most (a customer with an address, an order with a custom line item; when no single record shows every structure, the few that together do, at most five), chosen by which fields a record carries and never by their values, and the load reads that result before it sends the rest. The Import API has no dry run, so no offline stage can show that it accepts the shape a mapper sends; a refused shape now costs one failed operation instead of one per record. `imported` sends the rest; `unresolved` (a reference arriving on its own) sends it with a warning; `validationFailed`, `rejected`, `partiallyImported`, `canceled`, a result that stays `processing` for two minutes and a result that cannot be read stop the stage and everything after it, name the record and the API's errors, and create no store. The request bodies of a dry run show that request (`load-requests.json` flags it as `canary`), and an executed run records the result, with every record of the request, under `canary` in `load-result.json`.
